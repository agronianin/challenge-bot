# Состояние на 9 ноября 2026 года

MVP частично реализован. Документация сверена с исходниками и конфигурацией; сборка приложения, запуск контейнеров, Telegram и восстановление БД в текущей работе не проверялись. Старые отметки о готовности не заменяют проверку текущего запуска.

## Реализовано

- Регистрация пользователей, роли, первичная настройка максимума подтягиваний, русский и английский интерфейс.
- Личные настройки и хранение времен напоминаний; административное меню, назначение администраторов и CSV-импорт.
- Создание программ с расписанием и выходными, пауза, удаление, ручная перевыкладка дня.
- Вступление в один челлендж и выход с сохранением истории.
- Подбор упражнений, ежедневные групповые публикации и персональная нагрузка в личке, видео с текстовой заменой.
- PostgreSQL/JPA, отдельные миграции Liquibase, Docker Compose, внешние конфиги и ротация логов.

Подробные сценарии и формулы описаны в [Promt.md](Promt.md).

## Не завершено и известные ограничения

- Нет пользовательской отметки выполнения (есть только модель/таблица `Completion`), отправки напоминаний, статистики и просмотра своих активных программ.
- Нет персонального снимка нагрузки: изменения каталога, настроек или максимума пользователя влияют на повторную личную выдачу.
- Telegram-вызовы выполняются внутри транзакции БД, но не откатываются вместе с ней. Ошибка отправки не всегда мешает пометить день опубликованным: возможны пропуски и дубли при частичных сбоях; защиты для нескольких экземпляров недостаточно.
- Scheduler не догоняет дни, пропущенные во время простоя. Автоматического завершения программы нет (`ACTIVE`, `SCHEDULED`, `PAUSED`), поэтому участие может продолжать блокировать вступление в другую программу.
- При импорте нового видео остается старый `file_id`; подбор может вернуть меньше упражнений и превысить желаемый лимит типов.
- Серверный запуск и обновление без потери данных не подтверждены; обновление зависимостей не завершено. Docker-сборка пропускает тесты; сейчас есть один класс `ExerciseSelectorTest` с тремя unit-тестами.

## Организация репозитория

Правила разделены по областям с маршрутизацией из корневого `AGENTS.md`. Приватные данные, конфиги, логи и стартовый набор перенесены в `.local/`, исключены из Git и Docker build context. Compose использует новые пути, локальные порты и mount видео; повторная инициализация конфигов не перезаписывает настройки. Замечания к конкретным данным хранятся в приватном README набора. Проверены конфигурация Compose, пути и mounts, передача аргументов команд, защита конфигов от перезаписи, ссылки документации и неизменность данных по SHA-256.
