# Продукт и поведение

Telegram-бот для групповых фитнес-челленджей. Администратор создает программу, бот публикует упражнения в группе и персональную нагрузку в личных сообщениях. Цель MVP — добавить к этому отметки выполнения, напоминания и историю прогресса с сохранением данных после рестарта. Реализованное и оставшиеся задачи разделены в [Status.md](Status.md); запуск описан в [README.md](README.md).

## Сценарии

- Роли бота: `USER` и `ADMIN`, независимо от роли администратора Telegram-чата. Первый администратор назначается в БД; следующих можно добавить через `requestUsers` в личном административном меню.
- Первичная настройка пользователя требует максимума подтягиваний `maxPullUps`. Личное меню позволяет менять максимум и язык, добавлять, просматривать и удалять времена напоминаний.
- Администратор создает челлендж в личном диалоге: выбирает группу через `requestChat`, длительность, время публикации, timezone (кнопки или корректный `ZoneId` вручную), число упражнений и типов, частоту выходных. Старт — завтра, после сводки требуется подтверждение; дни создаются заранее. Рост нагрузки берется из конфигурации приложения, в диалоге не задается.
- Во время административного сценария доступна отмена с очисткой состояния и возвратом в главное меню.
- Управление программами: пауза, перевыкладка последнего опубликованного дня, удаление с отдельным подтверждением. Удаление физически удаляет программу, дни, задания, участия, отметки и записи сообщений; чат сохраняется.
- Вступление по кнопке «Участвовать» доступно для `ACTIVE` / `SCHEDULED` после первичной настройки. Допускается одно активное участие, включая программу на паузе. Повторное вступление отклоняется и не пересылает задание. При успешном вступлении отправляется сегодняшний день, если он уже опубликован.
- «Сдаюсь» деактивирует все текущие активные участия пользователя, сохраняя историю.

## Публикация и нагрузка

- Scheduler раз в минуту проверяет `ACTIVE` / `SCHEDULED` и публикует сегодняшний запланированный день после `post_time` в timezone программы.
- В группе публикуются упражнения, комментарии, видео и кнопка участия, без персональных повторений. Активные участники получают личное задание с количеством повторений или секунд.
- `rest_day_frequency = 0` отключает регулярный отдых; `N > 0` дает выходной после каждых N тренировочных дней. В выходной отправляется сообщение об отдыхе без упражнений.
- Подбор исключает `enabled=false`. Первый слот берется из `selection_group=1`, остальные — только из упражнений без группы. Единственное упражнение группы `1` может повторяться ежедневно; другие непустые группы сейчас не используются.
- Подбор детерминирован по ID, учитывает ранее использованные упражнения и типы предыдущего календарного дня. При нехватке вариантов ограничения типов смягчаются; обычный пул допускает повторы после исчерпания. Если свежих упражнений осталось мало, выдача может быть неполной.
- Базовая нагрузка: `baseReps * (1 + growthPercent * (dayIndex - 1))`, округление по настройке `ceil` / `floor` / `round` (по умолчанию `ceil`). Затем применяется `max(0.2, maxPullUps / 10.0)` с округлением вверх и прибавляется `static_reps`. При отсутствии максимума множитель равен 1; при `is_static_reps=true` результат равен только `static_reps`.
- Индекс дня календарный, включая выходные. Базовая нагрузка сохраняется в `day_exercise.reps`; личная пересчитывается при отправке из текущих настроек, упражнения и максимума пользователя. Персонального снимка пока нет.
- Перевыкладка использует сохраненный набор упражнений и пытается удалить прежние сообщения группы по `program_day_message`. Удаление может не удаться; личные задания повторно не рассылаются.
- Видео сначала отправляется по Telegram `file_id`, затем с диска; при отсутствии файла используется текст.

## Данные и язык

Схема определяется [changelog](db/liquibase/changelog.xml) и Java-моделями, а не отдельной копией списка колонок в документации. Основные данные: пользователи, чаты, упражнения и типы, программы и дни, задания, участия, сообщения публикаций, настройки напоминаний и отметки выполнения.

Язык выбирается из сохраненного `tg_user.locale`, затем языка Telegram, затем `ru`; поддерживаются русский и английский. В Java сохраненный код — `TgUser.localeCode`, разрешенная локаль запроса — transient `TgUser.locale`. Внешние переводы Docker имеют приоритет над встроенными. Незаконченные диалоги хранятся в памяти и теряются при рестарте; сохраненные программы и участия остаются в БД.

## Требования к завершению MVP

- Отметка выполнения привязана к пользователю и дню, уникальна для этой пары и хранит время. Должны различаться отсутствие участия, невыполнение и выполнение.
- Напоминания отправляются активным участникам в выбранное время, не отправляются за уже выполненный день; невозможность написать пользователю обрабатывается корректно. Сейчас настройки хранятся на уровне пользователя в `user_reminder`.
- Нужны статистика дня, список участников, личный прогресс и рейтинг.
- Нужны сохранение персональной нагрузки и уточнение окончательной формулы коэффициентов; отдельный `exercise_multiplier` пока не реализован.
- Повторные действия и перезапуски не должны дублировать публикации и отметки или менять историю. Это целевые требования, текущий scheduler полностью их не гарантирует.
