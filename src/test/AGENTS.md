# Тестирование

- Перед Java-тестами читай [правила Java](../main/java/AGENTS.md), а перед проверкой Telegram-flow — применимые правила bot-слоя.
- Над тестовым классом кратко опиши по-русски проверяемую область; над тестовым методом — сценарий и ожидаемый результат. Внутри комментируй только неочевидную подготовку, ограничения и ожидания.
- Проверяй значимое поведение и результат, избегай тестов, зеркалящих вызовы реализации. Объём проверок соразмеряй риску; используй существующие проверки, не добавляй тесты ради покрытия.
- Используй Java 25 и корневой `./mvnw`; обычная проверка — `./mvnw clean test`. Сборка Docker с `-DskipTests` не заменяет тесты.
- Для интеграционных запусков используй отдельные одноразовые БД и отдельный тестовый токен. Пустой токен или отключение polling не отключает scheduler: не подключай тесты к рабочей БД.
- Инфраструктуру и миграции считай проверенными только после реального запуска; для миграций дополнительно читай [db/liquibase/AGENTS.md](../../db/liquibase/AGENTS.md). Отмечай, что проверено фактически и что осталось.
